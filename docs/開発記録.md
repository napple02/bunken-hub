# 開発記録

文献ハブの、これまでの経緯・設計の判断・未確認事項・次にやることの記録。最終更新: 2026-10-10

## 1. 目的と前提
- 論文の「探す・本文を手に入れる・控える」を、既存サービスをつないで1画面で済ませる**個人用**の入口
- 検索エンジンとストレージは作らない（Google Scholar・CiNii・Google ドライブ等の再開発はしない）
- 利用者は大学・研究機関に所属していない → **本文の入手ルート**を最重視。日本語文献もそこそこ重視
- 隣のリポジトリ [edu-research-watch](https://github.com/napple02/edu-research-watch)（教育研究の月次・週次の収集）が「何を読むか」を見つけ、こちらが「どう手に入れて控えるか」を担う

## 3. 設計の判断と理由
- **サーバーなしの静的ページ**：維持費ゼロで、置き場所は GitHub Pages。個人データを預かるサーバーを持たない
- **台帳は localStorage**：ブラウザを消すと失われるので、(a) バックアップを2週間していないと知らせる、(b) `navigator.storage.persist` を頼む、(c) 同期を用意した
- **同期は GitHub のシークレット Gist**：Google ドライブ・Dropbox は、利用者側で OAuth クライアントの登録が要る。Gist はトークン1つで済み、ブラウザから直接呼べる。代わりに「URL を知っていれば読める」ので、画面に注意を明記し、トークンと API キーは同期しない
- **同期のマージ**（`lib.js` の `mergeSync`）：文献ごとに `updatedAt` が新しいほうを採用。削除は「墓標」で伝え、365日で捨てる。同時刻なら文献を残す。2端末が同時に push しても、各端末が手元の状態を持つので、次の同期で合流する
- **Service Worker はネットワーク優先**（3秒で見切って控えを使う）：画面のファイルが新旧混在しないようにするため。論文検索の外部 API には介入しない。控える一覧（`sw.js` の `SHELL`）は、テストで漏れを検出する
- **CSP は `script-src 'self'`**：トークンを端末に保存するので、スクリプトを差し込まれても動かないようにする。`connect-src` は `https:` を許可している（`doi.org` の内容交渉が Crossref・DataCite・JaLC などへ転送され、通信先を絞ると書誌の取得が壊れる恐れがあるため）。インラインのスクリプトとイベント属性は使わない
- **Google Scholar は画面内に出さない**：公式 API がなく、規約上スクレイピングもしないため、検索リンクだけを用意
- **有料の論文を無料にはしない**：合法に公開されている版と、正規の入手手段（購入・NDL の複写・図書館・著者への依頼）だけを案内する

## 5. 実機で最初に確かめること（マージ・Pages 反映後）
1. DOI（例 `10.1038/nature14539`）で、書誌と「無料版」が出るか。メールアドレスを登録した場合に Unpaywall の結果が加わるか
2. 日本語のタイトル（例「分子模型 教育」）で、CiNii・NDL の候補が出るか。出なければ、画面の注記とブラウザのコンソールを控える
3. 設定で GitHub のトークン（gist の権限だけ）を入れ、「接続して同期」。別の端末で同じトークンを入れて、台帳が届くか。失敗したら画面の文言を控える（CORS・権限・利用制限の切り分けに使う）
4. Android で「アプリとして追加」→ 他のアプリの共有から文献ハブを選び、論文ページの DOI が開くか。iPhone は共有の受け取りに非対応（ホーム画面への追加のみ）
5. 台帳の「Obsidian ノート（ZIP）」を Vault に展開して、frontmatter・一覧が崩れないか
6. ウォッチの週報の「文献ハブで入手ルートを見る」を押して、その DOI がすぐ調べられるか（Pages の URL が `https://napple02.github.io/bunken-hub/` で合っているか）

## 6. 既知の制約
- iPhone の Safari は、共有メニューからの受け取り（Web Share Target）に対応していない
- 同じメモを2端末で同時に書き換えた場合は、あとから保存したほうが残る（文献単位のマージ）
- シークレット Gist は、URL を知っている人が読める。メールアドレスと台帳の内容が入る
- 台帳が数千件規模になると、同期データ（Gist）が大きくなる。書誌の軽量化（参照文献の ID を落とす）はしている
- アイコンの元の図柄は `scripts/make-icons.mjs`（Playwright が必要）

## 8. 検証の方法
- 単体テスト：`npm test`（依存パッケージなし。GitHub Actions でも自動実行）
- ブラウザでの通しの確認：`npm run e2e`（Playwright と Chromium が必要。使い方は `tests/e2e/harness.mjs` の冒頭）。外部 API と GitHub の Gist は模したデータで、2端末の同期・オフライン・共有・★とタグ・ZIP・はじめの設定・CSP を確かめる
- 構成のテスト（`tests/pwa.test.js`）：manifest とアイコンの整合、`sw.js` の控え一覧の漏れ、`index.html` が参照する id の存在、CSP の設定、インラインのスクリプトが無いこと
